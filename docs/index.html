How it worksOne config, two protocols, real timing

1. Describe your process in YAML

Tags, units, addresses and a behaviour (sine, ramp, random walk, step, constant). This is a trimmed excerpt of the bundled examples/pump_station.yaml:

tags:
  - name: tank_level
    type: float32
    unit: "%"
    address: 0
    initial: 50.0
    behaviour: {type: sine, min: 0, max: 100, period_s: 600}

  - name: pump1_running
    type: bool
    address: 0
    initial: true
    writable: true
    behaviour: {type: constant}

scenario:
  - at: 120
    tag: pressure
    fault: spike
    magnitude: 3.0
    duration_s: 15

2. Run it in Docker

No local Python setup required:

docker compose up --build

This starts the bundled pump station process on Modbus TCP port 5020 and OPC UA port 4840.

3. Point your gateway or HMI at it

Connect over Modbus TCP to localhost:5020 (unit id 1), or over OPC UA to:

opc.tcp://host:4840/otlab-sim/

Register map

Fault injectionFaults on a schedule, not on luck

Stuck

The tag freezes at its last value. Tests whether your HMI/historian notices a sensor that has silently stopped updating.

Spike

A fixed offset is added for a set duration. Exercises alarm thresholds and operator alert logic on a repeatable trigger.

Drift

An offset that grows linearly over time. Good for testing slow-degradation detection and predictive-maintenance rules.

Offline

The Modbus listener actually stops — connections are refused, not just stale. Tests gateway failover and watchdog timeouts against a device that has truly dropped off the bus.

FAQShort answers

Does this replace a PLC?

No. otlab-sim simulates the data your PLC would expose over Modbus TCP / OPC UA (with realistic movement and faults) so you can test the layers above it — SCADA, HMI, gateways, historians. It does not run ladder logic or control real I/O.

Does it run on Windows?

Yes, via Docker (recommended) or a local Python virtual environment; both are documented in the repo README.

Can I use it commercially?

Yes. The core simulator is MIT licensed — use, modify, and redistribute it, including in commercial projects, at no cost.

How do I model my own devices?

Write a YAML file listing your tags (name, type, address, behaviour) as shown in examples/pump_station.yaml, or open an interest thread if you'd rather have us build it for you as a custom simulated plant.

How do I contact you?

Through GitHub issues on the otlab-sim repository — that's where features, bugs and pro/custom interest are tracked.
